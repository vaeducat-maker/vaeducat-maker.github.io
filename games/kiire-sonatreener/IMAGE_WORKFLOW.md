# Sõnatreener — проверенный способ добавления изображений в карточки

Дата проверки: 16.10.2026. Рабочий пример: **Inimeseõpetus → Урок 2 — Tervisenäitajad**.
Пользователь подтвердил по скриншоту с Android, что картинки показываются в карточках.

## Что сработало

**Встраивать настоящие пиксели WebP прямо в JavaScript урока как `data:image/webp;base64,...`, не загружая SVG-файл-обёртку.**

Проверенная реализация — файл `inimene-tervisenaitajad-lesson.js`:

```js
const WORD_IMAGES = {
  "pulss": "data:image/webp;base64,UklGR...", // полная base64-строка файла
  "süda": "data:image/webp;base64,UklGR..."
};
const wordImage = et => WORD_IMAGES[et] || '';
```

В словаре и в обеих сторонах карточки используется один и тот же `wordImage(et)`:

```js
'<img src="' + wordImage(et) + '" alt="" class="tervis2-flash-img">'
```

Изображение находится **вне текста ответа** и отображается на обеих сторонах карточки.
На основе реальной реализации: 15 изображений WebP, 15 разных `data:` URI; сохранить уже действующую логику тренировки.

## Алгоритм для новых уроков

1. Подготовить хорошие, стилистически единые изображения по одному на слово. Для карточки **лучше вырезать только картинку без готовых подписей**, чтобы подпись не раскрывала перевод и не дублировала текст интерфейса.
2. Оптимизировать изображения в WebP (умеренное разрешение и вес для телефона).
3. Закодировать *байты WebP*, а не SVG-разметку, в base64. Полный источник начинается с `data:image/webp;base64,UklGR...`.
4. Добавить `const WORD_IMAGES = {...}` в JS нужного урока, ключи должны точно совпадать с начальной формой слова в `WORDS`.
5. В рендере списка слов и обеих сторон карточки поставить `<img src="...">` на основе `wordImage(et)`. Оставить короткие размеры CSS с `object-fit: contain`, адаптивные для телефона.
6. Обновить номер версии JS в `index.html`: например, `lesson.js?v=новая-версия`. При необходимости обновить `data-build`.
7. Проверить JS на синтаксис, количество изображений и точность соответствия словам. Проверить непосредственно браузерную отрисовку и затем попросить проверить на устройстве пользователя. **Не говорить, что пользователь видит исправление, пока не получено подтверждение.**

## Что не сработало (не повторять)

- Путь вида `./tervis2-images/word.webp`, когда на самом деле в GitHub сохранён `word.svg`: все изображения ломаются.
- Простой перевод пути в `.svg`, где SVG — обёртка с вложенным `<image xlink:href="data:image/webp;base64,...">`: у пользователя по-прежнему не отобразились картинки.
- Несколько обновлений `?v=` сами по себе не чинят неправильный формат изображения.

## Обязательная проверка сохранности уроков

При добавлении иллюстраций не менять оригинальные упражнения, жирные ответы, построчные переводы, словарь, логику `✓/✕`, обратные карточки, другие предметы и уроки. Прежде чем изменять приложение, читать **актуальную** версию файлов репозитория GitHub.

Практический вывод: **в этом проекте надёжно заработали непосредственно встроенные WebP data URI внутри JS урока**. Использовать этот рабочий шаблон при последующих иллюстрированных уроках.
