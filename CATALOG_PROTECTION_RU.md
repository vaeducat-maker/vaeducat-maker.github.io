# EDUKASS · защита каталога материалов

Начиная с v122, опубликованные материалы защищаются реестром `data/catalog.json` и контрольным снимком `releases/catalog-v121.json`.

## Жёсткие правила

1. Ранее опубликованный материал нельзя просто удалить из реестра.
2. Постоянный URL ранее опубликованного материала нельзя менять.
3. Материал нельзя перевести в архив без `ownerApproval: true` и заполненной причины `archiveReason`.
4. Для каждого опубликованного материала проверяются страница, карточка в нужном каталоге, превью и все заявленные файлы скачивания.
5. Для платного материала обязательно поле `purchaseUrl`; платный файл в публичный репозиторий не кладётся.
6. Перед выдачей новой сборки должен пройти `node scripts/catalog-guard.js` и быть создан `RELEASE_REPORT_RU.md` со строкой «ВЫПУСК РАЗРЕШЁН».

## Что проверяет GitHub

Workflow `.github/workflows/catalog-guard.yml` автоматически запускает тот же контроль после каждого push в main. Если материал исчез или его постоянная ссылка изменена, workflow становится красным и показывает конкретный продукт.

Важно: при текущем режиме GitHub Pages эта проверка служит автоматической сигнализацией и контролем релиза. Полностью технически запретить Pages публиковать красный commit можно отдельным переходом на deployment через GitHub Actions/branch protection; это не включалось в v122, чтобы не менять работающую схему публикации без отдельного решения владельца.

## Публичные метаданные

Для материалов с `metadataSync: true` файл `data/catalog.json` является каноническим источником заголовка, категории, типа цены, описания, постоянного URL, превью и связанных действий. Публичные HTML-представления содержат только размеченные генерируемые копии этих значений, чтобы статический сайт сохранял SEO и работал без клиентского JavaScript.

Поле `qrUrl` задаёт постоянный печатный адрес вида `https://edukass.ee/<id>/`. Генератор синхронизирует его статическую redirect-страницу с каноническим `page`; проверка блокирует изменение постоянного QR URL и отсутствие маршрута.

- Обновить размеченные страницы: `node scripts/material-metadata.js --write`.
- Проверить, что ручных расхождений нет: `node scripts/material-metadata.js --check`.
- Внутренние ориентиры хранятся в объекте `internal` и генератором не выводятся.

`scripts/catalog-guard.js` запускает эту проверку вместе с обычным контролем каталога, а workflow отдельно проверяет сценарии со старым значением и удалённой привязкой поля.
